## Task 9: PNAS golden fixture bump procedure

### When to regenerate

Regenerate fixtures when a formatting rule changes behavior (new rules, changed
heuristics, changed output). The golden test will fail if the pipeline output
no longer matches the frozen expected file.

### How to regenerate

```sh
# Step 1: Regenerate expected.tex (source-level golden) and expected.txt (PDF text).
# Requires: latexmk, pdftotext on $PATH for the .txt file.
make pnas-fixture

# Step 2: Run the golden tests to verify.
go test -tags=pdfverify ./pkg/format -run TestGoldenPNAS -v

# Step 3: Commit the updated fixtures.
git add testdata/pnas-fixture/main_pnas.expected.tex
git add testdata/pnas-fixture/main_pnas.expected.txt  # if regenerated
git commit -m "chore: bump PNAS golden fixtures after rule change"
```

### What each file does

- `main_pnas.tex`: Frozen input (the "before" state). Do NOT modify unless
  adding new test coverage for a rule.
- `main_pnas.expected.tex`: Expected output of `Apply(src, {PDFFix: true})`.
  Regenerated by `go run testdata/pnas-fixture/gen_expected.go`.
- `main_pnas.expected.txt`: Whitespace-normalized pdftotext output of the
  expected PDF. Only generated when latexmk and pdftotext are available.
  Used by `TestGoldenPNAS` for text-layer verification.
- `latexmkrc`: Build configuration for the fixture.
- `gen_expected.go`: Helper tool that runs the pipeline and writes the
  expected output.
